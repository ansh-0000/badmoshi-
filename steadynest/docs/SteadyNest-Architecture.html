CLIENT → VENDOR
No direct path, ever. Not for maps, not for AI, not for a receipt.
WHY IT MATTERS
Keys never ship in a bundle anyone can unzip. Vendors stay swappable — MSG91 for another SMS provider is a one-file change. And every third-party call is logged, rate-limited and cached on our side, which is the only reason a pre-revenue app can afford Maps and Gemini at all.
02 Authentication flow
A phone number in, two tokens out
No password ever exists, so none can leak. The code is hashed before it is stored, dies in ten minutes, and can only be spent once. The access token is short-lived on purpose — the refresh token is the one that matters, and it is replaced every single time it is used.

03 Rent autopay flow
Eleven debits, and a plan for the one that fails
A standard Delhi lease is eleven months, so the mandate is written for eleven debits, not "until cancelled". The pre-debit notice at T-24h is not a nicety — it is required, and it is also the moment a tenant tops up their account.

04 Security layers
Seven layers, read from the outside in
Each layer holds on its own. Getting past one does not open the next — an attacker with a valid token still meets authorization, and one who gets past authorization still meets a query scoped to a single owner's rows.
L7Detection & monitoring
structured audit log · failed-login spikes · webhook signature failures page me
L6Rate limiting
5 OTP/hr/number · 100 req/min/IP · 3 SOS/hr/user
L5Transport
TLS 1.3 only · HSTS · no plaintext fallback
L4Identity
phone + OTP · 15-min access · rotating refresh
L3Authorization
role gate + row-level ownership on every query
L2Input validation
zod at the route edge · parameterised SQL
L1Sensitive data handling
OTPs and passwords hashed with bcrypt, never stored raw. KYC documents encrypted at rest. SOS media deleted from the device once the server acknowledges it. Location kept for 90 days and only for the purpose it was collected — DPDP Act, purpose limitation.
05 Emergency SOS flow
It has to work on one bar of signal
The whole point of this feature is the moment it is used, and that moment is rarely well-connected. So the trigger is deliberate, the payload is small, dispatch fans out across three channels, and if there is no data connection at all the app hands the OS a pre-filled SMS instead of failing quietly.

DPDP NOTE
SOS collects the most sensitive data in the product — precise location and camera frames. Consent is taken at the moment the feature is set up, not buried at signup; the frames are deleted from the device after acknowledgement; and the event record is retained only as long as the safety purpose lasts. Write that into the privacy policy before this ships, not after.
